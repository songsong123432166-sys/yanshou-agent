# 直接修正规则

技能版本1.3.0，基础快照版本9。此文件限定直接修改范围，不授权联网、上传到新服务或替换用户原文件。

## 字段与符号

| 内容 | 字段 | 写法 |
| --- | --- | --- |
| 多维标签 | 任务类型、视听标签 | `人物参考\|动态参考`、`实体/IP｜动态`；两种竖线均可。`实体/IP`、`镜头/运镜` 中的斜杠保留。 |
| 参考素材 | 输入描述、场景、主体、总结、自然指令 | `<图片X>`、`<视频X>`、`<音频X>` |
| 定义与调用 | 场景、主体、总结、自然指令 | `<场景X>`、`<主体X>`；前文定义，后文调用编号，不要求反复描述外貌。 |
| 画面文字、花字、水印 | 输入描述、画面元素、自然指令 | `【LAUNDRY】`、`【HBO】` |
| 台词、演唱、喊叫 | 自然指令（细节） | `说道{你好}`、`演唱道{오늘은 안된다고}` |
| 背景音乐及变化 | 自然指令（细节） | `（背景音乐是管弦乐，中速偏慢…）`、`（背景音乐淡出）` |
| 音效、环境声、声音起止 | 自然指令（细节） | `<传来噼啪的燃烧声>`、`<唰唰的草丛摩擦声停止>` |

合法音乐描述允许嵌套素材标签、人声和歌曲名，例如 `（背景音乐是歌曲《You(=I)》，女声演唱道{오늘은 안된다고}，营造出俏皮氛围）。` 音效尖括号内可以是整段描述，不能当作非法编号标签。

用途错配需要语境判断，不自动更换括号。普通括号、外语引号或其他字段出现合法符号本身不是错误。

## 基础标点自动修正

| 项目 | 默认处理 | 例子 |
| --- | --- | --- |
| 中文叙述中的半角标点 | 按中文语境规范 `, ; : ! ? .`，保留英文、技术内容和数值 | `男子转头,随后停下.` → `男子转头，随后停下。` |
| 定义后的冒号 | 中文全角 `：` 保持，明确的半角 `:` 改为 `：` | `<主体1>:青年。` → `<主体1>：青年。` |
| 已知编号标签 | 统一半角尖括号并去掉标签内空格，不改编号 | `＜ 主体1 ＞` → `<主体1>` |
| 音频外层包裹符 | 明确的背景音乐用 `（）`、人声用 `{}`、音效用 `<>`；内部保留 | `(背景音乐轻快)` → `（背景音乐轻快）`；`｛Hello, world!｝` → `{Hello, world!}` |
| 缺失的段尾句号 | 只在非豁免正文段尾补；句中不补 | `说道{你好}` → `说道{你好}。`；`说道{你好}，然后转身。` 保持 |
| 已有句末标点 | 不重复追加，不制造 `。。`、`，。` | `说道{你好}。`、`Hello.`、省略号保留；句尾逗号/分号等保留并提示核对 |
| 完整多标签的分隔符 | 标签完整、均可识别时把逗号、顿号、分号或换行规范为竖线；已有两种竖线都合法 | `音色-相同，环境音-相同` → `音色 - 相同｜环境音 - 相同` |

标签文字、顺序以及 `实体/IP`、`镜头/运镜` 内部的斜杠保留。空标签、正文混入或无法识别标签边界时不直接替换。任务类型及视听元数据仍不补句号。

`{}` 台词/演唱、音乐及音效内部、`【】` 画面文字、引号字面量、英文、网址、路径、时间码和小数不因中文标点规范被改写。只开放明确外层包裹符的宽度规范及片段结束后的段尾句号。括号缺失、符号错配、把文字错包成台词等需要判断语义的情况，给推荐稿后由人工确认，不自动猜补。

## 分隔符两侧空格

时间段和标签中作为分隔符使用的半角 `-`，两侧各保留一个半角空格，多余空格或制表符收敛为一个；不改变分隔的时间数值或标签词语。例如 `0-2秒` → `0 - 2秒`、`实体/IP-相同` → `实体/IP - 相同`、`参考-严格编辑-改` → `参考 - 严格编辑 - 改`。

英文单词连字符、负数、网址/路径、代码、音频内部、画面文字和引号字面量保持原样。此规则不把其他范围符号改成 `-`。`｜` 是全角竖线，`|` 是半角竖线，两者仍然合法；本条不要求给竖线两侧加空格。

## 时间段分段

仅在自然指令中，把 `0-2秒`、`2-8秒`等主时间段独立成段，段间空一行；不足一个空行时自动补齐，已有更多空行不压缩。`第2秒`、`第4秒`等段内时间节点不强制换段；保留其中原有换行。不判断时间先后、重叠或时长，不修改时间数值。

```text
0 - 2秒，<主体1>奔跑。第1秒，转头。

2 - 8秒，<主体1>停下。第4秒，微笑。
```

台词 `{}`、画面文字 `【】`、音乐/音效片段、引号字面量及技术内容内部出现的时间不拆分。其他字段不按时间段重排。分段后按已有段尾标点规则检查，不改正文词语。

## 段尾标点

任务类型、`similarity_label`、`video_similarity_tag`、`audio_similarity_tag`，以及已知同义导出字段 `task_type`、`subtask_type`、`similarity_tag`、`视听标签` 不补句号，不改标签文字；仅按上述明确规则规范完整标签的分隔符。未知字段不擅自解释为元数据。

其他字段每个非空行按一段检查，空行和原空白保留；内容为“无”也需句末标点。已有 `。！？!?`、英文句点和省略号保留，不叠加句号；逗号/分号/冒号结尾需核对，不追加成 `，。`。人声/画面文字跨行时，不在其内容内部追加标点。

- `说道{你好}，然后转身。`：保持。
- 段尾 `说道{你好}`：补为 `说道{你好}。`。
- 段尾 `说道{你好。}`：补为 `说道{你好。}。`。
- `说道{你好}。`：不重复补。
- `{}` 或 `【】` 缺闭合符：提示核对，保留不明确的内容，不猜测闭合位置。

## 仅转人工与停用项

主体定义不能重号，编号从1连续；总结/自然指令不能引用未定义主体；每个已定义主体必须在自然指令中明确引用。描述中的“音色同<主体2>”是引用，不是重复定义。缺失主体不自动补编号或动作；对白及画面文字中的字面标签不代替实际主体引用。

错别字即使看似明显也不在这个 Skill 的直接修改范围。需要判断内容类别、改变正文词语、纠正主体映射、判断不明确的标签分隔关系或补不明括号时，保留原文并列出待复核项。

属性冲突、衍字/叠词冗余和重复标签前缀不检查、不提示、不修复。不得以病句、错字或标点为名绕过停用规则。

文件无法可靠解析、Caption 列/工作表有歧义、目标格是公式、输入不属于支持的结构化 Caption 时，不修改该部分并明确标注未处理。遇到这种情况不能改查其他列。
