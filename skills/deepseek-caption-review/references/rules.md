# Caption 规则：技能1.9.0 / 字段版本10 / 自动规则版本10

本文件是团队当前标准；脚本快照来自同一项目，来源与哈希见 `RULES_MANIFEST.json`。其他技能或通用写作习惯不能覆盖这些业务规则。

## 新版12字段

按以下顺序，每个标题独立成行，两个井号后一个半角空格；每个字段内容结束后留一个空行，包括最后一个字段：

```text
## 任务类型
## 提示
## 参考关系标签
## 视觉标签
## 听觉标签
## 输入描述
## 基调
## 场景
## 主体
## 画面元素
## 总结
## 自然指令
```

- `画面元素`必须存在。没有原文依据时可补空标题，并标“缺少字段 / 内容待核对”；不得自动填“无”。已有字段留空单列“字段内容为空”，不与缺少标题混淆。原始缺字段即使补上也保留原始记录。
- `similarity_tag`、`video_similarity_tag`是“视觉标签”的旧英文名，统一输出为 `## 视觉标签`。中文 `自然指令（细节）`、`自然指令(细节)` 统一标题。完整且归属明确的 `brief_captions`、`subject` 可按已知别名处理，旧定义前缀可补为编号标签。
- `自然描述`也是`自然指令`的标题别名：检查时读取其正文，不因为标题写法不同就判全部主体漏写；字段规范时仅改标题为`## 自然指令`，保留原文。
- 旧 `task_type` 已填已知子任务标签时，只改标题为“任务类型”。`subtask_type` 为明确生成提示语时归“提示”，为已知子任务标签时归“任务类型”；多个新旧字段冲突时保留原文待确认。旧根任务“参考”、未收录的任务含义或无法确定的归属不猜映射，报告保留已提供的题目ID。
- 中文任务类型值包括但不限于人物参考、场景参考、九宫格/少宫格；不把示例当成完整枚举，不改任务含义。
- 参考关系标签的 `yes` / `Yes` / `no` 转为“是 / 否”；单个标签内容保留，标签分隔符输出为半角 `|`，全角 `｜` 自动转换；其余元数据原文保留。实体/ip、镜头/运镜中的 `/` 是标签内容，不拆开。
- 规范字段末尾为一个空行；除下述自然指令时间段和切镜处排版外，保留各字段正文内部原有段落、空格和场景定义/编号，不以整理标题为由按句重排。输出新副本，保留输入。

三个标签标题以 `## 参考关系标签`、`## 视觉标签`、`## 听觉标签` 为准；英文 `similarity_label`、`video_similarity_tag`、`similarity_tag`、`audio_similarity_tag` 继续识别。已知英文标签值使用项目当前词表转换；未知值保留并提示核对，画面文字和音频正文不翻译。

## 默认安全修改

1. 规范明确的标题、字段别名和顺序，补空的缺失标题并报告。
2. 已写明编号的主体、场景、图片、视频、音频补尖括号或去标签内空格，不改数字，不凭“她/他们”新增标签。画面文字及音频内部出现的字面标签不处理。
3. 中文叙述中明确的半角 `, ; : ! ? .` 按语境规范为中文符号；已有编号标签外层 `＜＞` → `<>`，明确背景音乐外层括号统一 `（）`，人声外层 `｛｝` → `{}`。内部内容保留；不做全局NFKC，不改英文、网址、时间码、小数、全角字母数字。外层包裹不完整时不猜闭合位置。
4. 非元数据字段的非空行视为一段，缺约定的句末标点时补外层句号。空行、跨行人声/画面文字内部不补；“无”作为已存在正文需补成“无。”。
5. 仅自动纠正固定词表：`眼晴→眼睛、帽孑→帽子、袖孑→袖子、鞋孑→鞋子、胳搏→胳膊、篮色→蓝色、帐蓬→帐篷、账篷→帐篷`。音频、画面文字、引号字面量和技术标记内部不改。模型不能自行扩大词表。

6. 自然指令中的主时间段（如 `0-2秒`、`2-8秒`）独立成段，段间空一行。同一时间段内切镜至少3次（至少4个镜头）时，在时间戳后写“镜头多次切换”，段内“第X秒”不强制换行；不足3次时，只在明确切镜处另起一行，普通动作时间点保持原段。不改秒数和时间逻辑，不拆分台词、音乐/音效、画面文字、引号或技术字面量内的时间。

切镜数只依据受保护原文之外明确写出的“镜头切换”“镜头切至/切到”“切镜”等描述；推拉摇移不算切镜。时间段开头用于承接上一段的切镜不计作段内额外切镜；已有“镜头多次切换”视为已声明多镜头段，保留原有段内换行。没有明确切镜依据时不猜镜头数；脚本不读取素材来推断镜头。音频、画面文字及引号里的切镜词和时间均不参与统计。

示例（至少3次切镜）：

```text
0-8秒，镜头多次切换，<主体1>站立。第2秒，镜头切换，转头。第4秒，镜头切至侧面。第6秒，切镜，微笑。
```

示例（不足3次切镜）：

```text
0-8秒，<主体1>站立。
第2秒，镜头切换，转头。第4秒，镜头前推。
```

句末标点豁免：任务类型、参考关系标签、视觉标签、听觉标签（兼容 similarity_label、video_similarity_tag、audio_similarity_tag），以及已知旧字段 task_type、subtask_type、similarity_tag、视听标签。其他非空正文段落按上面的约定处理。

`说道{你好}，然后转身。`不在句中大括号后补句号；段尾`说道{你好}`补成`说道{你好}。`。段尾`说道{你好。}`补为`说道{你好。}。`，内部台词句号不能代替外层标点。保留已有句号、问号、叹号；不做省略号或句尾逗号的语义猜改，不追加成 `，。`。已有英文句点保留。

## 分隔符两侧空格

仅任务类型和视听标签中作为分隔符使用的半角 `-`，两侧不留空格；按算法拼写统一为 `实体/ip-相同`。例如 `实体/IP - 相同` → `实体/ip-相同`、`参考 - 严格编辑 - 改` → `参考-严格编辑-改`。不改变标签的含义，不对时间范围自动加减空格。

时间范围（如 `0-2秒`、`0 - 2秒`）保留输入写法。英文单词连字符、负数、网址/路径、代码、音频内部、画面文字和引号字面量保持原样。此规则不把其他范围符号改成 `-`。`｜` 是全角竖线，`|` 是半角竖线，标签输出统一用半角 `|`，全角 `｜` 自动转换；竖线两侧不留空格，已有两侧空格自动去掉。

## 基础标点自动修正

| 项目 | 默认处理 | 例子 |
| --- | --- | --- |
| 中文叙述中的半角标点 | 按中文语境规范 `, ; : ! ? .`，保留英文、技术内容和数值 | `男子转头,随后停下.` → `男子转头，随后停下。` |
| 定义后的冒号 | 中文全角 `：` 保持，明确的半角 `:` 改为 `：` | `<主体1>:青年。` → `<主体1>：青年。` |
| 已知编号标签 | 统一半角尖括号并去掉标签内空格，不改编号 | `＜ 主体1 ＞` → `<主体1>` |
| 音频外层包裹符 | 明确的背景音乐用 `（）`、人声用 `{}`、音效用 `<>`；内部保留 | `(背景音乐轻快)` → `（背景音乐轻快）`；`｛Hello, world!｝` → `{Hello, world!}` |
| 缺失的段尾句号 | 只在非豁免正文段尾补；句中不补 | `说道{你好}` → `说道{你好}。`；`说道{你好}，然后转身。` 保持 |
| 已有句末标点 | 不重复追加，不制造 `。。`、`，。` | `说道{你好}。`、`Hello.`、省略号保留；句尾逗号/分号等保留并提示核对 |
| 完整多标签的分隔符 | 标签完整、均可识别时把逗号、顿号、分号或换行规范为竖线；全角竖线统一转换为半角 `\|` | `音色-相同，环境音-相同` → `音色-相同\|环境音-相同` |

推荐稿同样检查节选旁边的原文标点：原文已经有外层句号时，不会因建议片段漏摘该句号而再追加；展示和应用均使用核对后的实际替换。

标签文字、顺序以及 `实体/ip`、`镜头/运镜` 内部的斜杠保留。空标签、正文混入或无法识别标签边界时不直接替换。任务类型及视听元数据仍不补句号。

`{}` 台词/演唱、音乐及音效内部、`【】` 画面文字、引号字面量、英文、网址、路径、时间码和小数不因中文标点规范被改写。只开放明确外层包裹符的宽度规范及片段结束后的段尾句号。括号缺失、符号错配、把文字错包成台词等需要判断语义的情况，给推荐稿后由人工确认，不自动猜补。

## 符号合同

| 内容 | 符号 | 示例 |
| --- | --- | --- |
| 主体/场景定义和调用 | 半角尖括号 | `<主体1>`、`<场景1>` |
| 参考素材 | 半角尖括号 | `<图片1>`、`<视频1>`、`<音频1>` |
| 多标签拼接 | 半角竖线 `\|`（两侧无空格） | `人物参考\|场景参考` |
| 人声、对白、演唱、喊叫 | 半角大括号 | `说道{Hello, world!}` |
| 音效、环境音及起止 | 半角尖括号 | `<传来噼啪的燃烧声>` |
| 背景音乐特征及变化 | 中文圆括号 | `（背景音乐淡出）` |
| 画面文字、花字、水印 | 方头括号 | `【LAUNDRY】` |

音乐可嵌套人声、歌曲名及素材标签；音效尖括号内可是一整段描述，不能误当非法编号。普通括号、比较符号及外语标点不能仅凭形状报错。用途错配需要语境支持，先提建议供确认。

## 主体检查

- 主体定义的前缀编号从1连续。编号重复检查分别统计主体字段的 `<主体n>`、场景字段的 `<场景n>`、输入描述的 `<图片n>/<视频n>/<音频n>`；同字段内定义和描述内引用都计次。不同字段不合并计数，总结和自然指令允许反复引用。`<图片1>` 和 `<视频1>` 不算重复。主体定义集合仍只取定义前缀，不把描述引用当作新定义。
- 总结、自然指令中不应引用未定义主体。
- 每个已定义主体必须在自然指令中以标签明确引用；只在总结出现不算，台词/画面文字内部的字面标签不算。
- 缺失引用只提示并给出有依据的候选，不能自动编造动作或把场景事实补出来。
- 场景定义与编号按原数据保留；同字段重复 `<场景2>` 会提示，但不自动改成 `<场景3>`。场景未在后文出现不报错。

## 需要人工确认

语法结构错误、词表外疑似错别字、指代/主体引用问题、需要判断语义的标点和符号类别。只给明确依据；可执行候选须是当前字段的可准确定位的原文片段加一个推荐改后片段；有多种合理表达时可先推荐最小改法，并说明采用的理解与待核对点，其他正文保持原样。

音频内部默认不改。若明确提出纯标点候选，需用户已核对素材并明确批准，才能使用专门的音频标点确认参数；内部文字、空白和包裹符不因此开放。画面文字始终保留。缺少事实依据时仅提示人工按素材定稿。

## 完全停用

属性冲突（含跨字段颜色/服饰/材质不一致）、衍字/叠词冗余、重复标签前缀的合并删除。不修正重复前缀；同字段编号重复仍按上述范围报告。属性冲突和叠词不检查、不提示、不修正，不伪装为病句、错字或标点问题。不挑时间戳逻辑，不要求所有场景/画面元素在后文引用。不按“更优美”润色句子。
